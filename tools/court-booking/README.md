# 订场秒抢（court-booking）

球馆订场小程序（微赛 wesais SaaS）自动抢场工具。每天 9 点场馆放"今天+2天"的场地，
本工具在放场瞬间自动查场 + 下单锁场，人在 6 分钟内去小程序付款即可。
**纯本地工具，不部署线上服务器。只做小程序做不了的事：抢。看场/付款用小程序。**

## 入口

| 入口 | 说明 |
|---|---|
| **双击 `run_web.bat`** | 网页版（推荐）：贴 token → 点「开抢」→ 等响铃 |
| `run_snipe.bat` / `python snipe.py snipe` | 命令行备份通道 |
| `run_observe.bat` / `python snipe.py observe` | 取证观察（不下单，见下） |

## 网页版流程

1. 贴 N 个 token（主号+小号+…，各点「检测」变绿）
2. 目标自动显示：**只抢周末**——周四 9 点放周六、周五 9 点放周日，
   其他日子页面明说"没有周末场放场日"
3. 点「🔥 开抢」：8:59:55 起密集轮询 → 放场秒拉矩阵 → **多号独立盲抢**
   （各抢各的，互不干扰，期望各得一块场）→ 响铃 → 各号 6 分钟内分别付款

**滑窗匹配**：9-12 区间内找最早的连续可订段（同起点长段优先，尾段可延 1 小时）。
常态 9-11 是 0 元锁格，实际首中 **11:00-13:00**；11-12 被秒则落到 12-13；
若 0 元格真有窗口（见取证），同一逻辑天然抢到最早段。

折叠区还有：**测试下单**（日期+场地+整点起止+账号，真实订单不付款 6 分钟自动
取消，平时验证链路/捡漏用）；**取证观察**。

## token 更新（每次实战前做一次，2分钟）

1. PC 微信打开球馆小程序，Fiddler 抓包（Filters 只显示 api.wesais.com 防刷屏）
2. 随便点一条请求 → Request Headers → 复制 `Authorization` 整串
3. 贴页面「检测」，或写进 `config.json` 的 `accounts[].token`
4. 双号都要：微信切到小号再抓一条

> token 有效期短（实测隔天失效），每次抢之前换新的。config.json 已 gitignore。

## 取证观察（9-11 是不是根本没法抢）

**已有结论（2026-11-02 周三实战+取证实锤）**：0 元格=内部圈场，周末 9-11、
**工作日白天 9-14 全是**（15 点起才有价 36/60 元）。放场首帧 0 元格会短暂
`is_lock=false`（假窗口，当日 22/24 格"可订"），但下单**必被拒**（服务端
message 为空，28 连拒实录），数分钟后全部转锁。`bookable()` 已排除 0 元格，
滑窗只会锚定有价时段。observe 模式保留（新场馆/规则变化时复核用）：
放场前 10s 就位，放场后每 0.5s 快照矩阵 2 分钟，diff 落盘
`evidence/<日期>-observe.jsonl`。正常抢场也会存放场首帧矩阵到 evidence/。

## 异常处理

- 等待循环到点必退（2026-10-30 死循环事故修复，`test_snipe.py` 锁行为）
- 等待期每 5 分钟 token 复验，失效页面红条报警（开枪前换 token 还能救）
- 网络抖动：关键请求重试（对时/验token 3 次、下单 2 次），探测失败不中断
- 放场 5 分钟未出现 → 明确失败提示（放场时间可能变了）
- 所有日志落盘 `logs/snipe-日期.log`
- `python test_snipe.py` 跑单测（目标推导/滑窗匹配/区间解析）

## 接口原理（抓包逆向自 booking1.har）

| 接口 | 作用 |
|---|---|
| `POST /field/wxFieldBuyPlan/getDateList` | 探测放场：新日期出现=9点放场了 |
| `POST /field/wxFieldBuyPlan/getList` | 12场×13槽矩阵，含 sku/价格/is_lock |
| `POST /shop/order/create` | 下单锁场（表单POST，无签名无风控头） |
| `POST /field/businessBase/getNowTimeStamp` | 服务器时间，用于对表 |

可订判定：`is_lock==false && lock_status==0 && is_overdue==false` **且 `price!="0.00"`**
（0元格=内部圈场，见下）。鉴权：
`Authorization` 头带 JWT。轮询克制：放场前 5 秒起 0.35s/次×30s，之后降为
1s/次，总时长最多 5 分钟，抢到即停。个人自用工具，别改参数去轰服务器。
